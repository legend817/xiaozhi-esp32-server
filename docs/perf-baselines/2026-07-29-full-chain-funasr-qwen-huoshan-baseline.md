## 观察

- 当前核心链路的首音频 P50 约 2.79s，其中 ASR 约 1.81s，占比最高。
- LLM 首 token 约 0.49s，火山双流首音频约 0.78s，这两段已相对可控。
- 组合端到端完成 P50 达到 20.5s，主要因为识别文本 `开饭时间早上9点至下午5点。` 触发了较长回答，TTS 播放段数多；它不适合作为短问短答总耗时指标。
- 后续完整链路应补一条“短回答语音样例”，例如用户音频内容为 `你是谁` 或 `现在几点`，否则总完成时间会被回答长度主导。

## 后续建议

1. 准备 2～3 条固定中文短语音样例：
   - `你是谁`
   - `现在几点`
   - `讲个笑话，二十字以内`
2. 对每条样例统计：
   - 说完后到首音频
   - 说完后到播放结束
   - ASR / LLM / TTS 分段耗时
3. 重点优化 ASR：
   - 对比单独部署 `FunASRServer`
   - 对比流式 ASR
   - 评估是否把本地 FunASR 从主服务进程拆出去，降低阻塞和资源竞争
