## 二、全链路语音流程

```
用户说话 → Opus → PCM → VAD(550ms静音尾)
  → ASR FunASRServer2Pass (wss://...:10095)
    → tool_router (lightweight_router)
      ├─ 企业类 → 预热缓存 → 命中 → 直接回复
      │                      未命中 → RAGFlow HTTP → LLM → TTS
      ├─ 工具类 → 调用插件 (天气/新闻/音乐)
      └─ 普通聊天 → LLM 直接生成

LLM → ResponsePolicy(字数预算) → StreamingTextSegmenter(切句)
  → TTS 火山双流 (zh_female_wanwanxiaohe_moon_bigtts)
    → Opus → WebSocket → 设备播放
```

## 四、缓存数据流

```
┌───────────────────────────────────────────────────────────────┐
│                       启动预热                                 │
│                                                               │
│  服务启动                                                      │
│    → 读 config["plugins"]["search_from_ragflow"]              │
│    → 取 dataset_ids (当前: QA_v3)                             │
│    → GET /api/v1/datasets/{id}/documents                      │
│    → GET .../chunks (分页, 每页100条)                          │
│    → 解析 "问题：xxx\t回答：xxx"                               │
│    → 写入 Redis:                                              │
│        key   = cache:warmup:{normalized_question}             │
│        key   = cache:warmup:alias:{category}:{subject}        │
│        key   = cache:warmup:cat:{category}                    │
│        ttl   = 7天                                            │
│                                                               │
│  ┌─── Redis ──────────────────────────────────────────┐       │
│  │  cache:warmup:中科生创集团何时成立并注册 → 答案       │       │
│  │  cache:warmup:alias:main_business:中科生创集团 → 答案│       │
│  │  cache:warmup:cat:main_business → 答案               │       │
│  │  cache:ragflow:{sha256} → 上下文文本                 │       │
│  └────────────────────────────────────────────────────┘       │
│                                                               │
│                     运行时查询                                 │
│                                                               │
│  用户问"公司主营什么业务"                                       │
│    1. match_warmup() → cat:main_business 命中 → 直接返回 ✅   │
│                                                               │
│  用户问"你们有什么合作机构"(冷门问题)                            │
│    1. match_warmup() → 未命中                                 │
│    2. cache_manager.get(RAGFLOW, sha256) → 未命中             │
│    3. RAGFlow HTTP → 结果 → 写入 Redis (7天)                 │
│    4. 下次同问题 → Redis 命中 ✅                               │
└───────────────────────────────────────────────────────────────┘
```

## 五、当前性能基线（短语音 P50）

| 环节 | 耗时 | 备注 |
|------|------|------|
| VAD 尾延迟 | 550ms | 固定等待，每轮必交 |
| ASR fun_server_2pass | ~700ms | 远端 FunASR，边说边识别 |
| ← **预热缓存命中** | **~1ms** | **字段问答，跳过全部后续环节** |
| RAGFlow HTTP 检索 | ~300~500ms | 仅在预热/缓存未命中时发生 |
| LLM 首 token | ~495ms | Qwen3-30B-A3B |
| TTS 火山双流首音频 | ~878ms | 短文本 |
| **说完到首音频(预热命中)** | **~1.25s** | VAD + ASR + 缓存命中 |
| **说完到首音频(未命中)** | **~2.5s** | VAD + ASR + RAGFlow + LLM + TTS |

## 七、优化空间（按优先级）

### P0 — 高收益、低工作量

| 优化 | 问题 | 方案 | 预期收益 |
|------|------|------|----------|
| **staged_first_reply** | RAG 查询期间设备静默等待 | 设置预播"我查一下知识库" | 填补 ~1~2s 静默期 |
| **VAD 450ms** | 当前 550ms 尾延迟偏保守 | 改配置到 450ms，验证不截断 | 每轮省 100ms |
| **Qwen 思考模式确认** | 不确定当前推理后端是否产生隐藏 think token | 在请求中显式关闭 | LLM 首 token 可能再降 |

### P1 — 需要验证的工作量

| 优化 | 问题 | 方案 |
|------|------|------|
| **直答预算收紧** | 字段型问题有时仍会输出长答案 | 对直答路径直接限制输出字数 |
| **别名覆盖扩展** | "主营业务是什么"这种无主语问句无法分类 | 给 `build_enterprise_faq_cache_alias` 增加无主语匹配 |
| **embedding 语义缓存** | alias 匹配覆盖不如 embedding 广 | 对缓存 key 用 embedding 相似度替代精确匹配 |

### P2 — 远期方向

| 优化 | 说明 |
|------|------|
| 并发架构异步化 | 每连接 5 线程 → 20 路并发时线程数爆炸 |
| 多知识库路由 | 快答库做字段直答，长资料库做 LLM 生成 |
| Triton + CosyVoice 自部署 TTS | 替代火山双流，降低网络/云成本 |
| ASR 2pass 时序加固 | 处理 VAD 判停与 ASR final 之间的竞态 |
| 真机测试自动化 | 音频回放 + WebSocket 协议回放 |
| Reranker 优化 | 在 RAGFlow 检索后加一层 reranker 提升准确率 |

## 八、核心设计原则

1. **RAGFlow 是唯一数据源** — 不需要维护任何本地文件、Python 清单
2. **首次命中的预热 + 冷门问题的自学习** — 流量越用越快
3. **字段问答不走 LLM** — 固定的、确定的、不需要推理的，直接从缓存回答
4. **预热只配智能体绑定的数据集** — 不会拉取无关数据
5. **别名 + 类别兜底** — "公司电话"和"中科生创集团电话"都能命中
