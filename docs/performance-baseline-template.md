## 5. 结果

服务端延迟日志统一以 `LATENCY` 开头，可用下面命令采集：

```bash
docker logs xiaozhi-esp32-server --since 30m 2>&1 | grep LATENCY
```

当前打点字段：

| 日志事件 | 含义 |
| --- | --- |
| `asr_start` | ASR 收到完整语音片段，开始识别 |
| `funasr_generate` | 本地 FunASR `model.generate` 推理耗时 |
| `asr_end` | ASR 完成，包含识别文本长度和是否有声纹结果 |
| `chat_start` | 一轮用户问题进入 LLM/TTS 编排链路 |
| `llm_first_token` | LLM 首个有效文本 token |
| `llm_end` | 当前 LLM 流式输出结束 |
| `tool_end` / `tool_error` | 工具调用完成或异常，包含工具名和耗时 |
| `ragflow_retrieval` | RAGFlow `/api/v1/retrieval` 请求耗时 |
| `tts_first_segment` | 第一段可送 TTS 的文本切分完成 |
| `tts_first_audio` | 第一批音频数据准备发送到设备 |
| `chat_end` | LLM/工具阶段结束，TTS 可能仍在处理 |
| `tts_end` | TTS 音频阶段结束，包含本轮汇总 |
